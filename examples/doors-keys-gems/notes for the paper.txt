● Data Pipeline: Format Conversion and Experiment Selection

  Background

  The human behavioral data used in this study was originally collected as part of a prior
  experiment (CogSci 2021) using an older version of the Doors-Keys-Gems PDDL codebase (the
  project-blocks branch). The current modeling framework, however, uses a modernized PDDL
  implementation (PDDL.jl ≥ 0.2.x, master branch) that is incompatible with the original problem
  file format. To run both the SIPS baseline and the proposed hierarchical abstract planner on the
  human trajectories, the data had to be ported to the new format.

  ---
  Experiment Selection

  The original dataset contains 16 human trials spanning 12 distinct gridworld maps (problems 1–12).
   New-format PDDL problem files — compatible with the current codebase — exist only for problems
  4–7. Problems 8–12 do not have corresponding new-format definitions and would require significant
  reverse-engineering effort to reconstruct. Since the core comparison between SIPS and the abstract
   planner does not depend on any specific subset of maps, we selected the 8 experiments whose maps
  are available in the new format (problems 4–7), covering a diverse range of map complexities,
  key-door configurations, and goal structures. The 8 dropped experiments (problems 8–12) are
  excluded solely due to this technical incompatibility, not for any methodological reason, and
  their exclusion introduces no systematic bias in the comparison between models.

  ---
  Format Conversion

  Two structural differences existed between the old and new PDDL formats:

  1. Coordinate system

  The old format uses a bottom-origin coordinate system (y=1 is the bottom row, y increases upward).
   The new format uses a top-origin system (y=1 is the top row, y increases downward). All item,
  door, and agent positions in the new problem files are transformed as:

  new_y = height + 1 − old_y

  where height = 9 for all maps used. The x-coordinate is unchanged. This transform was applied when
   the new problem files were originally created, so no additional conversion was needed for the
  problem files themselves.

  2. Unlock action syntax

  The old format represents the unlock action as (unlock key direction), where direction specifies
  which adjacent cell the door is in relative to the agent (e.g., (unlock key2 left) means "unlock
  the door one step to the left"). The new format replaces directional references with named door
  objects: (unlock key doorN) (e.g., (unlock key2 door2)).

  To convert each unlock action, we traced the agent's position step-by-step through the trajectory
  up to the unlock action, identified the adjacent cell in the specified direction, and matched that
   cell's coordinates to the corresponding named door in the new problem file. This mapping was
  verified against the new-format problem files for all 8 experiments. Movement actions (up, down,
  left, right) and pickup actions (pickup item) are syntactically identical between formats and
  required no changes.

  3. Gem naming consistency

  When the new-format problem files for problems 4 and 6 were originally created, the gem objects
  were assigned names in a different order than in the old format. Since the human plan files
  reference gems by name (e.g., (pickup gem1)), this mismatch would cause trajectory simulation to
  fail — the agent would arrive at the correct physical position but attempt to pick up a gem whose
  name did not match the object at that location in the new problem file.

  To resolve this, we reordered the gem coordinates in the new problem files to match the original
  naming convention:

  - Problem 4: gem2 and gem3 positions were swapped
  - Problem 6: gem1 and gem3 positions were swapped

  This change affects only internal object labels, not physical positions, trajectory actions, or
  human judgment data. The experimental validity and fairness of the model comparison are
  unaffected.
                                                                                                     
                                                                                                 
                                                                                                    
  ---                                                                                               
  Format incompatibility between experimental branches. The human data was collected using the      
  project-blocks branch of the codebase, while the current modeling framework runs on the master    
  branch. These two branches diverged significantly in their PDDL representations — not only in     
  action syntax and coordinate systems, but also in how objects are named and ordered within problem
   files. This created a subtle but critical issue: even after correctly transforming coordinates   
  and converting action syntax, the gem objects in problems 4 and 6 were named in a different order
  between the two branches, causing trajectory simulation to fail silently (the agent would reach   
  the correct physical position but reference the wrong gem by name). This kind of naming
  inconsistency is difficult to detect without manually cross-referencing every object position
  between the old and new problem files, and could in principle affect other aspects of the data
  beyond what was identified here. More broadly, this highlights a reproducibility risk when
  experimental data and modeling code evolve independently across branches — future projects should
  enforce a single canonical PDDL format from the point of data collection onward.
